# Windows 报告文件权限问题

## 实际复现
宿主用户执行默认演示并覆盖原 `reports/demo` 时，`os.replace` 返回 WinError 5；三个旧输出文件无法由宿主用户读取，而输出目录本身可访问。生成到新的输出目录成功。

独立回归把普通输出目录的探针文件 DACL 与发布后的三份报告文件比较。旧发布方式把 `TemporaryDirectory` 中的私有文件直接移动出来，三份报告保留受保护的私有 DACL，均与普通目录继承权限不同。

这为先前本地文件链接的 ERR_ACCESS_DENIED 提供了具体原因；仅归因于应用内浏览器限制的解释不完整。

## 处理范围
应用保留私有暂存，先完成三件套生成，再通过最终输出目录中的普通临时兄弟文件发布，使新文件继承输出目录权限。不能以全局放宽权限或运行管理员命令作为产品逻辑。

旧文件因当前用户无修改 DACL 权限，不能直接 reset。主会话核实目录仅含三份合成报告后，将原目录保留为 `reports/.legacy-demo-sandbox`，重建 `reports/demo`，不删除旧结果。历史目录加入忽略列表；源数据与人工黄金集没有变动。

最终修复测试、重新生成报告及浏览器结果以本目录最新验收记录为准。
