# 独立评估计划

Evaluator 依据原始 DOCX 制定，实施者不得通过阅读人工黄金标签调整规则。

## 验收边界

产品代码可在无密钥条件下验证工程行为；真实模型准确率、实际费用、人工抽检和全新会话恢复需要相应证据，不能以规则演示的成功替代。

| 功能 | 独立检查 |
| --- | --- |
| F01 | UTF-8 BOM、GB18030、中文列名、引号内换行的 CSV 起始物理行；空行/无效日期的处理可解释；所有持久化字段和外发字段均脱敏；用户标识不会原样留存 |
| F02 | 主题/情绪/严重度枚举与类型严格验证；漏项、重复 ID、未知 ID 被拒绝；输入注入作为数据而非指令；付费请求前预算预留与超时约束 |
| F03 | 数量与主题覆盖不丢失；严重度和负向情绪聚合可复算；排序确定；单条反馈不会被重复计数 |
| F04 | 引用仅从本地脱敏数据回填；不存在、跨主题、重复用户的证据不能通过；单用户主题/空主题返回数据不足；摘要不得采用模型自由编造的数字和功能 |
| F05 | HTML 转义、无外部网络资源、搜索筛选、源码行号；用户内容不进入可执行 JS；非正常退出不输出貌似完整报告 |
| F06 | 60 条人工标签、36/12/12 配额；主题≥80%、严重度容差1≥70%、引用100%；对抗错误一票否决；空标签不得显示通过；结果附运行模式和费用口径 |

## 拟用攻击输入

- `</script><img src=x onerror=alert(1)>`、双引号、换行、Unicode 分隔符。
- 反馈正常但渠道列为邮箱、用户列为手机号；日期列混入邮箱或非法值。
- 多行反馈后再一行正常反馈，检查第二条引用的物理行号。
- 提示模型忽略指令、伪造主题和引用行号的文本。
- HTTP stub 返回重复、遗漏或额外记录；类型为布尔值的严重度；无 usage 或不合理 usage。
- 预算低于一次调用上限时确认 stub 收到 0 请求。
- 其余样本全部正确、仅一条对抗样本错误时确认总体不通过。

## 报告规则

没有运行证据即标为待验证。真实模型/人工验收未执行的指标单列，不把工程通过等同于产品验收通过。发现问题后向 Generator 发出具体复现，最多三轮复核。
