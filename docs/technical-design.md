# 技术设计

## 运行方式

Python 3.10+，优先使用标准库，不要求数据库、Node 或服务端。CLI 提供合成数据生成、规则演示/模型分析、生成 HTML、生成黄金集空模板和评测入口。具体命令以 README 和 CLI `--help` 为准。

## 数据流

CSV → 校验/脱敏 → 单条分类 → 主题聚合 → 有约束摘要 → 引用校验 → 静态 HTML 和 JSON 指标。脱敏在模型调用之前完成，原始敏感信息不能进入模型消息、结果、错误日志或 HTML。

建议记录结构包含稳定记录 ID、原始 CSV 物理起始行号、日期、脱敏文本、渠道和不可逆用户代号。CSV 应通过解析器处理引号和换行，禁止用简单按行拆分代替。无用户 ID 的数据不具备“不同用户”证据，应明确标识为未知身份。

## 模型边界

模型路径使用Chat Completions JSON HTTP接口。`--provider openai`使用OpenAI默认地址 `https://api.openai.com/v1` 和 `OPENAI_API_KEY`；`--provider compatible`保留可配置地址和 `FEEDBACK_API_KEY`、`FEEDBACK_BASE_URL`、`FEEDBACK_MODEL`。凭证不跨provider自动借用，不写入文件。规则模式完全离线，必须显著标注不能代表GPT或其他模型质量。产品API调用与Codex开发登录分别配置，不共享登录凭证或免费额度。

分类使用固定枚举、严重度区间和记录 ID 完整性校验；反馈作为不可信数据，禁止执行其指令。对注入样本隔离/保守分类并记录风险。对未知标签、漏项、重复 ID、非法 JSON、网络超时等明确失败，不能静默伪造成功。

摘要只允许使用当前主题的脱敏证据；引用由程序按行号提取，不接受模型自由生成的引文。对单条、空主题及有效用户不足，输出“数据不足”。机会点表述为需进一步验证的问题，不生成未证实的因果结论。

## 成本与故障

真实模型运行必须显式配置输入/输出每百万token的人民币单价、人民币预算和模型名；OpenAI入口使用官方默认地址，兼容入口需配置地址。预算不设默认付费承诺。请求前按最大输出估算预留费用，请求后按实际usage结算。缺少usage时标记费用未知并停止后续付费请求，不将其记为零。设置超时，失败不自动重试付费请求，不覆盖已有完整报告。

## 报告与评测

HTML 所有文本转义，不加载 CDN、远程脚本或字体，支持窄屏及打印。报告展示分析方式、合成数据说明、主题统计、证据和运行指标。

独立评测按稳定 ID/源行号匹配黄金集，检测缺失、重复、无效标签和样本数，不能仅评估匹配成功的子集。空白标签不能算正确，也不能被静默跳过。黄金集只供 Evaluator 与用户使用，Generator 不读取其标签；空模板由主会话或 Evaluator 生成。

## 三 Agent 工作记录

Planner 创建六项清单与验收标准；Generator 编写实现并自测；Evaluator 只读成果、运行检查、提出问题，主会话负责记录报告和更新状态。任何一项超过三轮返工需中止并报告。`harness/feature_list.json`、`harness/progress.md` 和验收/评估报告是新会话继续工作的入口。当前凭证和人工质量验收缺失必须保留为待办，不能被离线测试覆盖。

Codex读取根目录 `AGENTS.md`；角色使用 `.codex/agents/*.toml` 的 `name`、`description`、`developer_instructions`。`.codex/config.toml`仅开启子Agent并设置最多3个并发子Agent，不固定模型或修改全局账户设置。角色继承父会话的权限、provider、MCP与skills，不通过角色文件创建不同沙盒；只读和禁读黄金集为协作要求，需要强隔离时由执行环境另行提供。详细启动与恢复步骤见 `docs/codex-setup.md`。

## Windows 输出文件发布
先在私有暂存目录生成完整产物，再通过输出目录中新建的普通临时兄弟文件复制并逐文件替换，避免直接移动私有文件后保留原DACL。不通过放宽系统权限解决。每个文件单独替换，整体不构成三文件目录级原子事务；发布阶段I/O失败应重新运行完整分析。复制准备失败、首次替换失败的旧报告保留和临时文件清理均有回归测试。

## 报告呈现
报告沿用 `render_report(report)` 接口和原有分析数据结构。CSS与JavaScript作为同包资源维护，生成HTML时内联；最终页面不依赖资源路径或网络。炭灰配色、紧凑统计栏和五列主题汇总表服务于纵向报告阅读，主题顺序和统计仍采用已有聚合结果，不添加分析指标。

每个主题的前两条原话直接展示，其余放入原生折叠区。反馈明细使用独立tbody，筛选不得作用于主题汇总表；源行号锚点保持稳定。打印事件先保存浏览状态，再展开全部证据、显示全部明细；重复准备打印不覆盖最初状态，结束打印后恢复。打印CSS使用白底黑字并解除表格滚动和屏幕高度限制，保留来源与分析方式标记。
