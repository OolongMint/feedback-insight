# 需求分析

来源：根目录《AI 产品经理三 Agent 试跑计划：用户反馈洞察助手.docx》。本文是对给定需求的分析，没有进行外部竞品或市场调研。

开发环境现采用Codex，持久规则在 `AGENTS.md`，三角色在 `.codex/agents/*.toml`。此次平台迁移依据OpenAI官方的[项目规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[子Agent](https://learn.chatgpt.com/docs/agent-configuration/subagents)及[技能](https://learn.chatgpt.com/docs/build-skills)文档核对配置格式与继承行为；不改变以下产品需求和人工验收边界。

产品经理需要从 200–300 条杂乱反馈中，快速识别主题、严重程度、情绪，并能核对每条原话。交付物是 Python 命令行程序、离线 HTML 报告、评测脚本和可续接的三 Agent 工作记录。

最重要的失效方式是编造证据、隐私外发、提示词注入、评估集泄露及无证据的“通过”。先脱敏再调用模型；原话由程序从数据中提取，模型不能自由创作引用。任何模型质量结论都必须来自用户人工标注的黄金集。

当前没有真实反馈、人工标签、模型凭证或已确认单价。可使用明确标记的合成数据验证工程流程，用规则模式进行零费用演示；这些结果不能替代模型准确率或真实费用验收。

隐私边界：规则可以识别已知格式的手机、邮箱、订单号，姓名等非结构化信息需用户提供敏感词或先做人工脱敏审核。不得声称可以可靠识别任意姓名。保留原始 CSV 仅在用户本地，输出仅持久化脱敏数据。
