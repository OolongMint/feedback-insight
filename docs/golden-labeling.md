# 人工黄金集标注说明

`data/golden.csv` 只有样本行号和分组，没有答案。请由理解产品的人员独立填写。不要先看预测再复制标签，也不要让Generator读取黄金集。合成样例只能练习标注与评测流程，最终产品质量需要真实反馈。

## 操作
1. 备份空模板。按 `source_row` 在原始 CSV 找记录；它是物理起始行号，含多行字段时与电子表格记录序号可能不同。
2. 阅读脱敏文本并独立填 `topic`、`sentiment`、`severity`；有争议先记本地标注笔记，与另一位熟悉产品的人讨论。
3. 完成人工复核再填 `reviewed=true`。保持36条normal、12条boundary、12条adversarial，不能删除困难样本来提高通过率。
4. 用 `evaluate` 比较真实模型预测，另抽20条人工检查。对提示词注入是否改变行为仍需人工判断，不能以JSON合法或正则命中代替语义审查。

## 建议统一口径
一次只选一个最主要主题；混合主题优先标实际影响最大的诉求，并记录歧义。主题枚举与README一致。情绪是用户对体验的态度，区别于问题严重度；功能建议可以中性但优先级高。讽刺、引用指令与真的发出指令应依据上下文判断，不按照关键词机械标注。

| 严重度 | 标注参考 |
| --- | --- |
| 1 | 一般意见、正向评价，未描述使用受阻 |
| 2 | 不便、理解成本或非关键体验问题 |
| 3 | 关键操作受阻，但存在替代或可恢复 |
| 4 | 核心流程无法完成、明显损失风险 |
| 5 | 数据丢失、资金或安全等重大且持续影响 |

这是标注起点，具体业务可先统一定义；一旦用于正式评测，避免根据预测结果倒改答案。误判、分歧、Evaluator放水或误杀记入 `reports/retrospective.md`。
