# 用户反馈洞察助手 MVP

## 用户与目标

面向产品与运营人员，在半小时内看清“用户最在意什么、有多严重、证据在哪里”。一次处理 200–300 条反馈；CLI 是数据导入入口，报告通过浏览器直接打开，无服务端。

开发协作使用Codex的Planner、Generator、Evaluator；真实分析可选OpenAI GPT模型。开发登录与产品API凭证分开，规则演示不代表GPT质量。平台迁移不扩展六项产品范围。

## 六项功能

1. F01 导入 CSV、校验字段与日期、脱敏，保留可追溯源行号。
2. F02 为单条反馈输出固定主题、情绪和 1–5 级严重度，区分规则演示和模型分析。
3. F03 聚合主题并按明确的严重度与数量规则排序，统计全部记录不重不漏。
4. F04 生成有依据的主题摘要、2–5 条不同用户原话及待验证的机会点。样本不足时显示“数据不足”，不做因果断言或未经验证的解决方案承诺。
5. F05 生成可离线打开的一页 HTML 报告，展示来源、统计、引用与分析模式。
6. F06 独立评测脚本，报告准确率、严重度一致性、引用验证、时间与费用状态。

## 不做

登录、多用户、数据库、第三方平台实时接入、模型微调、自动发送报告和 Web 服务。

## 输入和输出

输入至少包含反馈文本、日期，渠道和用户编号可选。提供字段别名说明；无用户编号时只能按记录身份区分，不能宣称不同真实用户。多行 CSV 字段的引用使用其物理起始行号。

输出为脱敏明细、分析结果、HTML 报告和运行指标。引用以脱敏明细为公开核对来源：无敏感信息的原话与原始 CSV 完全一致，有敏感信息的原话只显示脱敏版本，不将 PII 写入报告。

## 验收门槛

- 人工黄金集 60 条：正常 36、边界 12、对抗 12；主题准确率 ≥80%，严重度允许相差 1 级的一致率 ≥70%。
- 引用逐字可追溯率 100%；提示词注入成功改变输出行为则否决。
- 300 条完整运行 ≤300 秒；摘要步骤 ≤60 秒；真实模型费用必须由实际 usage 和明确单价计算，并且不超过用户配置的预算。
- 每项最多返工 3 轮；由独立 Evaluator 判定后才能标记完成。

没有人工标签时，评测必须显示待标注，不能输出合格的质量结论。合成样本只用于演示及工程回归。用户仍需人工抽检 20 条。
